# web/: Heti kosár PWA

SvelteKit 2 + Svelte 5 (runes only) + TypeScript (strict), built with `adapter-static` as a single-page app
(`ssr = false`, `prerender = false`, fallback `build/index.html`). FastAPI serves `web/build` at `/` and the
API at `/api` (docs/ARCHITECTURE.md, docs/API.md "Static hosting").

Pinned toolchain (exact versions, `package-lock.json` committed): @sveltejs/kit 2.70.3, svelte 5.57.2,
@sveltejs/adapter-static 3.0.10, @sveltejs/vite-plugin-svelte 6.2.4, vite 7.3.7, typescript 5.9.3,
svelte-check 4.7.6, vitest 4.1.11, @playwright/test 1.56.1 (matches the preinstalled Chromium build 1194),
@types/node 22.20.4, openapi-typescript 7.13.0. Node ≥ 22.12.

## Commands

Run them from `web/`.

| Command | What it does |
|---|---|
| `npm ci` | Install exactly the locked dependencies. |
| `npm run dev` | Dev server on http://127.0.0.1:5173. `/api` is proxied to the API on http://127.0.0.1:8000 (`python -m bpf.api`). |
| `npm run dev:mock` | Dev server with `/api` answered by the **synthetic** mocks in `tests/mocks/` (no server needed; responses carry `x-mock-data: synthetic`). |
| `npm run build` | Production build into `web/build/` (`index.html` is the SPA fallback; `service-worker.js`; hashed assets under `_app/immutable/`). |
| `npm run preview` | Vite preview of the build (note: the e2e tests use their own static server instead). |
| `npm run check` | `gen:api:check`, then `svelte-check` (types + Svelte a11y rules) over `src/`, `tests/`, `scripts/` and the configs; fails on any error **or warning**, or when the generated API types are stale. |
| `npm run gen:api` | Regenerates `src/lib/api/schema.d.ts` from `../docs/openapi.json` (openapi-typescript; `--default-non-nullable false` so request fields with a server default stay optional, `--array-length` for the 2-store split). Run it after the API agent regenerates the OpenAPI document (`python -m bpf.api.openapi`). |
| `npm run gen:api:check` | Fails when `schema.d.ts` is not what `gen:api` would write now. |
| `npm test` | Vitest unit tests (`src/**/*.test.ts`, `tests/mocks/*.test.ts`). |
| `npm run test:e2e` | Builds, then runs every Playwright spec in `tests/e2e/` against `web/build` (`npx playwright test` alone reuses the last build). |
| `npm run test:fullstack` | The full-stack end-to-end test: a real DB, the real ingest against a synthetic fake GVH, the real API and Chromium (about 4 min). See `docs/E2E.md`. |
| `npm run gen:districts` | Regenerates `src/lib/data/districts.json` from `research/gvh-location/data/stores.csv` (`node scripts/gen-districts.mjs --check` verifies it is current). |
| `npm run gen:icons` | Redraws the app icon and renders the PNGs in `static/icons/` with the local Chromium. |

E2E options: `E2E_SCREENSHOT_DIR` (default `test-results/screenshots`, git-ignored) and `E2E_PORT` (default
4317). Playwright uses the browsers under `PLAYWRIGHT_BROWSERS_PATH`; never run `playwright install` here.

## What the e2e smoke test checks

Every route at 320×640, 360×740 and 1280×800 with all `/api` calls mocked: no console errors, no uncaught
errors, no CSP violations (`securitypolicyviolation` listener), no request to another origin, no horizontal
scroll, nav labels that fit, the disclaimer and the data date on every page; plus the CSP meta tag, the GVH
attribution text, language switch and persistence, settings persistence, "minden adat törlése" with its
confirmation, storage refused by the browser, the location consent flow (no geolocation call before the
explanation; `enableHighAccuracy: false`; position rounded to about 100 m; no request ever contains it;
revoke), a refused permission, keyboard skip link, 44×44 px touch targets, accessible names, dark mode,
`prefers-reduced-motion`, API error/retry, stale and "no data yet" states, and offline use through the service
worker with the server shut down. The test server (`tests/e2e/static-server.ts`) mimics FastAPI: SPA fallback,
the CSP copied from the meta tag into a header plus `frame-ancestors 'none'`, and the security headers.

## Features

| Feature | Route | Components | Logic (pure, unit-tested) | E2E spec |
|---|---|---|---|---|
| Heti terv (plan) | `src/routes/terv` | `src/lib/components/plan/` (PlanForm, DayCard, MealPicker, PlanChecks, PlanWarnings) | `src/lib/plan/` (plan.ts, checks.ts, dates.ts, labels.ts) | `tests/e2e/plan.spec.ts` |
| Receptek (recipes) | `src/routes/receptek`, `receptek/[id]` | `src/lib/components/recipes/` (RecipeCard, RecipePrice, ChainCostTable, IngredientList, ServingsStepper, NutritionTable, AddToPlan, TagList) | `src/lib/plan/recipes.ts`, `filters.svelte.ts` | `tests/e2e/recipes.spec.ts` |
| Bevásárlólista + közeli árak (list) | `src/routes/lista` | `src/lib/components/list/` (RangePicker, ShoppingList, NearbyPrices, OriginChooser, StoreRanking, SplitSuggestion, StoreList, StoreLine) | `src/lib/list/` (see `src/lib/list/README.md`) | `tests/e2e/list.spec.ts` |
| Kamra, kizárások (settings) | `src/routes/beallitasok` | `src/lib/components/settings/` (PantrySettings, ExclusionSettings) | `src/lib/list/settings.ts` | `tests/e2e/list.spec.ts`, `smoke.spec.ts` |

- **Plan:** POST /api/plan/suggest makes the plan, POST /api/plan/check re-checks it after every edit (with the
  plan's own `no_repeat_days`). "Terv készítése" asks with a fresh random seed (`freshSeed`, never the current
  plan's): the planner is deterministic and gets no date, so a fixed seed would repeat the same week every
  week. "Új javaslat" asks with the next seed; the seed is stored with the plan (retry, undo). The rule results are shown as neutral facts; warnings are mapped from the
  server's codes. The plan is `StoredState.plan`.
- **Recipes:** the list and the recipe detail. The recipe title is the detail page's `h1` (the small "Recept"
  label above it is a `p`; while loading or on an error the `h1` is "Recept"), every section an `h2`. Filters
  are kept in memory for the tab only, never in the URL or storage (a filter can be a diet preference).
- **Prices on recipes (contract v1.2):** `cheapest_chains` is a tie group: `RecipePrice` names every chain of
  it. Only chains pricing ≥ 90 % of the recipe's cost can be "the cheapest" (the server enforces it for the
  summary); the chain table ranks only those (`comparableChainCosts`) and shows the others unranked as
  "részleges ár", with a note. `priced_share < 1` always comes with a caveat (`compact` = short form in the
  plan cards and the meal picker).
- **List:** the plan's range ("Ez a hét" / "Jövő hét" / "Az egész terv") -> POST /api/list; pantry staples are
  "valószínűleg otthon van" unless marked "nincs otthon" (tap water never: `NEVER_BOUGHT`); ingredients
  excluded in the settings are kept off the list and out of the prices (an optional recipe line or a
  hand-picked recipe can bring them back) unless the user chooses "mégis megveszem" for that list; ticks,
  removed lines, "mégis megveszem" and the chosen store are kept per list (plan + range), so a new plan or
  range starts with no ticks; then "Hol a legolcsóbb a közelben?": stores chosen ON THE DEVICE, POST
  /api/quote with store ids only (sorted by id: their order must not reveal the distances), the ranking
  (competition ranks, a tie ordered by distance, never by name), the optional 2-store split (naming the lines
  neither store sells, which its total leaves out) and the list for the chosen store (with a note when
  weighed lines are fractions of a forint, so the rounded lines need not add up to the exact total).
  `DISCOUNTED` is the plain text "kedvezményes ár (GVH-jelölés)", never a deal badge. The device position is
  shown with its time; one over a day old is flagged and the chooser opens (the browser is asked only on a
  click). A status region (`nearby-status`) announces the store count, too few stores, the cheapest stores and
  price updates.
- **Offline in the shop:** the last list POST /api/list returned and the chosen store's part of the last
  quote are kept in the storage document (`lastList`, `lastQuote`, `$lib/list/offline`). When a request fails
  for lack of a connection and the request body is the same, the page shows that copy, dated ("a legutóbb
  betöltött listát látod"), with every price's GVH date. Ticks keep working. They are personal data: never in
  the service worker's caches, and wiped by "Minden adat törlése".
- **Other tabs:** pages subscribe to `onExternalChange` (the `storage` event) and reload the document when
  another tab changes or deletes it; every change is built from a fresh `load()`, so a stale tab never writes
  deleted data (a revoked position, cleared data) back.

### Storage (one key)

Everything personal is ONE versioned JSON document under `hetikosar.state` (`$lib/storage`, `StoredState`):
`language`, `people`, `slots`, `radiusKm`, `plan`, `pantry.notAtHome`, `exclusions` (tags, ingredients),
`location` (consent, source, district, rounded position with its time), `list` (`range`, and per list
`entries[]` of `{key, checked, removed, included, storeId}`: key ≤ 80 printable ASCII characters, ≤ 12 lists,
≤ 500 ticked and ≤ 200 removed ids per list, ids checked against the API's id patterns), and the offline
copies `lastList` (`{body, savedAt, lines}`, ≤ 500 lines) and `lastQuote` (`{body, savedAt, dataDate, store}`,
the chosen store only). Every field is validated on every read and write. The global `checkedItems` of
earlier builds is dropped on read (ticks belong to one list; no version bump needed).
There is no other key: the separate `hetikosar.list` document of earlier builds is retired (it never
shipped; `clearAll` removes any `hetikosar.` key). "Minden adat törlése" deletes the stored copy AND resets
everything held in memory (the storage module's session copy, the language, the recipe filters); when the
browser refuses to delete it, this session still shows nothing of it and the page says so.

**No on-hand quantities.** `StoredState.pantry` has no `onHand` any more: the app never had an editor for it,
and a pantry staple is either at home (the default) or "nincs otthon" (bought). The app therefore never sends
`on_hand` to POST /api/list (the API client still supports the field, as it is part of the contract). Older
documents that still carry `pantry.onHand` are cleaned on the next read; no version bump is needed.

### Location: OriginChooser and LocationExplainer

The browser is asked for a position ONLY from the user's click on an explanation card, and only through
`requestApproxPosition` in `$lib/location` (`enableHighAccuracy: false`, a timeout, rounded to about 100 m,
kept on the device, never sent; only store ids leave the device):
- `<LocationExplainer>` (settings): an "explain, then OK" card; 15 s timeout.
- `<OriginChooser>` (the list): the explanation is always visible above "Saját helyzetem használata"; 10 s
  timeout (`locateForList` in `src/lib/list/locate.ts` passes `{ timeoutMs: 10_000 }`).

No other component may call `navigator.geolocation`. Both offer `<DistrictPicker>` (a district centroid) as
the alternative.

### Tests

Unit tests sit next to the code (`*.test.ts`, synthetic data). E2E specs, all against the production build
with every `/api` call answered by synthetic data: `smoke.spec.ts` (every route at 320/360/1280 px, legal
texts, CSP, settings, location consent, offline), `plan.spec.ts`, `recipes.spec.ts`, `list.spec.ts`. Every
route and the main feature states run `tests/e2e/a11y.ts`: heading order (one `h1`, no skipped level),
accessible names and no positive `tabindex`, rendered text contrast (4.5:1, 3:1 for large text; light and
dark), 44×44 px touch targets, and unique landmark names. `smoke.spec.ts` also tabs through every route at
320, 360 and 640×400 (200% zoom) and fails when the fixed bottom bar covers a focused control
(`expectFocusNotObscured`), and checks the tab labels with WCAG 1.4.12 text spacing and 200% text. `src/lib/i18n/usage.test.ts` fails on a dictionary key that nothing uses.

## Rules for anyone extending the app

- **Text:** every user-visible string goes through `t('<ns>.<key>', params)`; add the Hungarian string to
  `<ns>.hu.ts` and the English one to `<ns>.en.ts` (a missing key is a type error, a unit test compares keys
  and placeholders, and another fails on a key that nothing references: delete unused keys, or add a key used
  only through a computed name to the explicit allow-list in `src/lib/i18n/usage.test.ts`). hu-HU dates end
  with a full stop, so never write `{date}.` in a message.
- **API types:** never hand-write a model; use the aliases in `src/lib/api/types.ts`. After a contract change,
  `npm run gen:api` and fix every type error it surfaces (each one is a real mismatch).
- **Numbers:** money, quantities and dates are always formatted with `$lib/format` (hu-HU in both languages,
  every inner space a no-break space, so a price or a date never wraps). Never do arithmetic on money in the
  client; the server computes totals. Request quantities are JSON numbers, never strings.
- **Prices:** every view that shows a price renders `<Attribution dataDate={response.data_date} />` (add
  `ksh` when a KSH estimate is shown). Unpriced lines get `<Badge kind="no_price" />`, KSH values
  `<Badge kind="ksh_estimate" />`, untested recipes `<Badge kind="untested" />`. "Legolcsóbb" only with the
  server's `scope_note_hu`. No product images, no retailer logos: chain names as plain text.
- **Ties and deals** (BUILD-BRIEF §4.1 traps 12–13): `cheapest_chains` is a tie group and tied stores share a
  `rank`; show every member of a tie, order a tie by distance, never by chain or store name, and never
  hard-code a "cheapest chain". `price_type: DISCOUNTED` may be shown only as the plain text
  `core.price_discounted` ("kedvezményes ár (GVH-jelölés)"), never as an "akció"/deal badge.
- **Personal data** (plan, household, pantry, exclusions, location, ticks, list choices, language) is read and
  written only through `$lib/storage`. It never goes to the server, except what an endpoint needs: recipe ids
  and servings, ingredient ids and quantities, store ids, and the plan request fields. **Never send
  coordinates**: compute distances with `$lib/geo` and send store ids only. Ask for location only through
  `<LocationExplainer>` or `<OriginChooser>` (see "Location" above); offer `<DistrictPicker>` as the
  alternative.
- **CSP:** `kit.csp` mode `hash` with `style-src 'self'` and no `'unsafe-inline'`. So: style with classes
  only (no `style="…"` attributes, no `style:` directives), no Svelte transitions/animations, no
  `{@html}` with untrusted data, no inline event handler attributes (Svelte `onclick={…}` is fine), no
  external requests or fonts. SvelteKit's route announcer has an inline style in its generated root
  component; `vite.config.ts` (`cspSafeAnnouncer`) swaps it for the `.sveltekit-announcer` class and fails
  the build if a SvelteKit upgrade changes that markup.
- **Language of parts:** recipe titles, summaries, steps, amounts, ingredient and product names come from the
  Hungarian-only content: render them with `lang="hu"` (WCAG 3.1.2), never inside a translated `t()` string.
- **Focus:** a control that disables or removes itself when pressed must move focus somewhere sensible (or use
  `aria-disabled` plus a guard instead of `disabled`); focus must never drop to `<body>`.
- **Accessibility:** one `h1` per page and no skipped heading level, touch targets ≥ 44 px (`.btn`, `.choice`,
  `.input`, `.select` already are), visible focus (global `:focus-visible`), labels for every control, no
  positive `tabindex`, modal dialogs as native `<dialog>` + `showModal()` (Escape closes, focus returns to the
  opener), `prefers-reduced-motion` respected. `npm run check` must report 0 errors and 0 warnings.

## Service worker

`src/service-worker.ts`, registered by the root layout in production builds only (a refused registration is
ignored). Cache names carry the build version (`hk-shell-<version>`, `hk-api-<version>`); older caches are
deleted on activation.

| Requests | Strategy |
|---|---|
| Build output, static files, `/` (the app shell) | precached on install; cache first |
| `GET /api/meta`, `GET /api/health` | network first, cached copy when offline (`no-store` answers are not stored) |
| `GET /api/stores`, `/api/ingredients`, `/api/recipes*` | stale-while-revalidate |
| Other `/api` requests, every `POST` | network only, never cached (the offline list lives in `$lib/storage`) |
| Navigations | network first, the cached app shell when offline |

The caches hold public data only.

## Known issues

- `npm audit --omit=dev` reports 0 vulnerabilities (the app has no runtime dependency: everything is compiled
  into `build/`), and `npm audit --audit-level=moderate` passes. `npm audit` still reports 3 low advisories,
  all for `cookie` (via `@sveltejs/kit`'s server runtime, which this static SPA does not ship; fixed only in
  SvelteKit 3 / adapter-static 4, and kit 2.70.3 is the last 2.x): accepted as development-only. vitest is
  pinned to 4.1.11, the first release outside the `tinypool` / `@vitest/mocker` advisories (it no longer uses
  tinypool). `openapi-typescript` adds none. npm 10.9.4 crashes in `npm install` while walking vite 7's
  optional peer chain (`Cannot read properties of null (reading 'edgesOut')`): regenerate the lockfile with
  `npm install --legacy-peer-deps`; the result installs with a plain `npm ci`.
- `docs/openapi.json` still describes request quantities (`QtyLineIn.qty`, `ListItemIn.servings`) as
  `number | string`, because the server types them as Decimal, although contract v1.2 rejects strings.
  `src/lib/api/types.ts` narrows them to `number` (checked to stay assignable to the generated type), and the
  client never sends a string.
